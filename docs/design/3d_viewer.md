Canvas demand rendering and private geometry/material disposal avoid continuous animations and mutation of shared GLB resources. SVG drawing remains usable without WebGL. This is an illustrative presentation extension, not a physical twin or diagnosis subsystem.

## Decorative flexible surface — 2026-10-10

### Performance revision and workspace coverage

The SVG implementation below is superseded by a passive Canvas2D renderer. `gridMesh` precomputes 50 desktop / 34 mobile polylines (1,160 / 796 vertices); each active frame draws one path, with no path-string construction or per-line DOM mutation. At most three ripples are retained. Pointer bounds are cached between resize/scroll events; smoothing uses elapsed time with a 65ms response constant. Canvas raster dimensions are capped at 1600×1000 and DPR 1.25. Active rendering aims for display cadence with a 30Hz fallback after slow draws; no frames are scheduled once input/pose and ripples settle. The 3D camera publishes a wake callback rather than forcing a perpetual polling loop. Hidden/offscreen/drawer pause and reduced-motion static rendering remain; touch scrolling does not trigger decorative waves.

`WorkspaceGrid` supplies one subtle fixed backdrop in the shared operations/research shell behind opaque cards/charts and controls, including dashboard, fleet, planning, inventory, simulator and supporting pages. Aircraft detail uses its own model-following stage grid instead of starting a second simultaneous workspace renderer. Mobile navigation/command-palette opening pauses the shared grid. Authentication/session screens and blueprint/part geometry retain their own surfaces. Missing Canvas2D support simply omits decoration; no evidence or actions depend on it. The earlier SVG/continuous-update description is historical.

`FlowGrid` adds a pale perspective SVG wire grid behind the aircraft only. Gaussian surface wells follow camera azimuth and aircraft transition position through a mutable presentation signal; passive pointer listeners create a local dip, outward decaying wave trails and a subtle cool soap-film sheen. The grid does not warp/blur foreground geometry, headings, data or controls and never intercepts input. It is a visual effect, not a physical/engineering simulation. SVG paths update at most about 30 Hz, stop offscreen/in hidden documents/while the component drawer is open, and dispose listeners, observers and animation frames on unmount. Reduced motion uses a fixed dipping grid without pointer/camera animation or ripples. No assets, dependencies, API values or geometry validation claims change. Earlier descriptions of a ripple-free stage are superseded by this explicitly requested decorative effect.
